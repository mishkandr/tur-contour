# ТурКонтур

ТурКонтур помогает специалисту по развитию туризма Владимирской области разобраться, какие программы затронуло изменение, как их скорректировать и какое улучшение позволит провести больше программ из наблюдаемого набора. Международная академия гостеприимства — заказчик пилота. Маршруты пилота охватывают Владимир, Суздаль и Кидекшу.

На карте можно переключать дни и группы, открывать паспорта объектов и сравнивать две версии программы. Если карта улиц недоступна, приложение показывает локальную схему с теми же точками и линиями переездов.

## Запуск

Нужен Node.js 22 или новее. Дополнительные пакеты устанавливать не требуется.

- На macOS откройте «Launch.command». Сервер выдаст свободный локальный адрес и откроет его в браузере.
- Из терминала выполните `node server.mjs` в папке проекта и откройте [http://127.0.0.1:4173](http://127.0.0.1:4173).
- Для сравнения вариантов и разбора свободных запросов можно подключить локальный Ollama с моделью `qwen3.5:4b`. Имя модели задаётся через `TUR_OLLAMA_MODEL`. Если Ollama недоступна, оператор всё равно может рассчитать, сравнить и согласовать программу вручную.

## Демо для защиты

Для повтора с исходными данными задайте пустой каталог состояния перед запуском. Например, в терминале `TUR_STATE_DIR="$(mktemp -d)" node server.mjs`. Рабочий журнал останется в прежнем каталоге.

1. На вкладке «Карта» выберите второй день программы группы из 18 человек. Нажмите на Суздальский кремль в списке точек, чтобы увидеть его на карте и открыть паспорт.
2. Нажмите «Снизить лимит в демо». Сервис прочитает вторую версию учебного аудита и запишет изменение 25 → 12 человек. Программа группы из 8 человек сохранится.
3. Переключите «Замена объекта» и «Два сеанса». Сравните точки и расписание. Два сеанса по 9 человек нужно согласовать с музеем. В блоке «Какие улучшения помогут» сравните варианты для того же набора групп и дат. У исходных двух программ после снижения лимита выполнима одна. Согласованный второй сеанс в расчёте возвращает возможность провести обе.
4. Нажмите «Открыть программу». Сравните варианты расписания, при желании попросите ИИ учесть замысел программы, затем нажмите «Согласовать вариант». Версия появится в журнале решений и останется на контроле при следующих обновлениях. Для группы из Китая откройте «Программа на китайском» и выгрузите TXT с расписанием, правилами для подгрупп и проверками перед поездкой.
5. На вкладке «Статистика» спросите, в какие месяцы за последние три года было меньше всего размещённых лиц во Владимирской области. Сверьте применённые годы, статус источника и месячные значения. В «Источниках» можно обновить ряды, увидеть журнал и сопоставить две учебные выгрузки размещения на 21–22 ноября.

### Проверка требований кейса

| Обязательный пункт | Что показать |
| --- | --- |
| Реальный внешний источник | «Источники» показывает статус подключений Wikidata и Росстата через Roschart |
| Статистика по запросу | Сервис выбирает ряд, ищет совместимый месячный выпуск и сравнивает заявленные периоды |
| Каталог из 15–30 объектов | 20 объектов из нескольких источников, из них 17 с опубликованными условиями маршрута |
| Мониторинг изменений | Две версии учебного аудита и журнал со старым и новым значением. Ошибки источников сохраняют последнюю копию |
| Оценка готовности | Паспорта со ссылками, датами, графиками, ограничениями и вопросами для подтверждения |
| Маршрут на два или три дня | Два дня Владимир → Суздаль, третий день в Кидекше. Расчёт проверяет даты, посещения, переезды, питание и ночёвки |
| Управленческая рекомендация | Сравнить число выполнимых программ до и после улучшения. Сезонная гипотеза связывает ночёвки, опубликованные графики и пробелы в условиях |
| Сценарий для китайской группы | Отдельная версия программы на упрощённом китайском и выгрузка TXT |

Вкладка «Маршруты» позволяет менять дату, размер и профиль группы, формат и длительность. Для природного и пешего форматов нужен подходящий подтверждённый объект в каталоге. Учебные условия можно выключить в параметрах.

## Роль ИИ

Код обновляет источники, рассчитывает показатели, проверяет ограничения, строит варианты маршрута и пересчитывает эффект каждого инфраструктурного сценария. Локальная модель помогает выбрать вариант, сохраняющий замысел программы, опираясь на рассчитанные остановки и расписания. Подсказка появляется по запросу пользователя. Специалист согласует конкретную версию маршрута. Согласование в интерфейсе фиксирует решение и оставляет бронирование и подтверждение поездки за специалистом.

## Происхождение данных

- Росстат через [API Roschart](https://roschart.ru/docs). Показатели «Численность размещённых лиц» и «Число ночёвок» по Владимирской области. Сервис ищет свежий совместимый месячный выпуск. Для воспроизводимости выпуск можно закрепить через `TUR_ROSSTAT_EDITION`. Месячные значения получены как разности накопительных итогов. При сбое используется последний доступный снимок.
- Wikidata через Wikibase API. Координаты и названия для части каталога. Для объектов опубликованы ссылки на сайты музеев и поставщиков или карточки Wikidata.
- Методика и контрольные объекты из двух таблиц МАГ. Условия визита в `data/demo-audit*.json` — учебные значения. Часы, лимиты, транспорт, бронь и язык обслуживания требуют подтверждения перед реальной поездкой.
- Опубликованные условия маршрута Владимир — Суздаль подключены по умолчанию из `data/published-*.json`. В паспортах и слое карты «Официальные графики» показаны часы на выбранный день, ссылки, условия записи, ограничения конкретных сеансов и вопросы для сверки. Снимок вручную сверили 17 ноября 2026 года. Основной [график ВСМЗ](https://vladmuseum.ru/ru/posetitelyam/times/index_rezim.php) покрывает период с 5 октября по 29 декабря 2026 года. Для других дат сервис обозначает пробел в графике. Оперативные места и факт брони у объектов проверяет специалист.
- Две учебные OTA-выгрузки показывают механику сопоставления предложений на ночь по дате заезда и числу гостей в номере. Карточки одинаковых отелей объединяются, а остатки разных источников отображаются отдельно. Фактическую доступность номеров для группы подтверждает отель.
- Внешние источники проверяются при запуске и раз в шесть часов работы сервера. Снимки, журнал изменений, согласованные версии и программы на контроле хранятся в `.runtime/state.json`. Переезды рассчитываются по схеме пилота. Фактический транспорт, брони и услуги подтверждаются отдельно.

## Подключение подтверждённых условий объектов

Если поставщики уже подтвердили условия для организованных групп, передайте абсолютный путь к согласованной JSON-выгрузке через `TUR_AUDIT_FEED_FILE`. Она загружается вместе с остальными источниками. Опубликованный график участвует в проверке конкретного времени. Квоты сборной экскурсии, вместимость отдельного зала и число номеров отображаются с указанной областью действия. Если файл временно недоступен или содержит ошибку, сервис сохраняет последний корректный снимок и показывает состояние источника. Условия вне периода действия требуют уточнения.

Верхний уровень содержит `version` (строка) и `objects` (объект с ключами из `data/catalog.json`). Каждая запись содержит `capacity` (человек), `minutes` (продолжительность посещения), `hours` (`[открытие, закрытие]` в часах местного времени), `off` (дни недели от `0` для воскресенья до `6` для субботы), `seasons` (`all`, `winter`, `spring`, `summer`, `autumn`), `language` (`interpreter`, `ru` или `null`), `access` (`true`, `false` или `null`), `booking` (`reservation` или `walk-in`), `sourceUrl` (HTTPS), `verifiedAt` (дата или время сверки ISO) и `validUntil` (включительная дата `ГГГГ-ММ-ДД`). В репозитории есть учебные условия. Выгрузка с подтверждением поставщиков подключается отдельно.

## Проверка

`node --test` проверяет ограничения расписания, пересчёт двух учебных программ, обработку выгрузки и согласование одной версии при повторном запросе. Тесты запускаются без открытия браузера и без запуска сервера приложения.

## Источники карты

- Карта улиц и реки используют данные [OpenStreetMap](https://www.openstreetmap.org/copyright). Для переездов между городами используются сохранённые линии [OSRM](https://project-osrm.org/). Соединения между отдельными остановками внутри города показаны пунктиром по прямой.
- Координаты 20 объектов и пяти населённых пунктов лежат в `data/map.json` со ссылками на источники. Для двух ресторанов показаны координаты комплекса, где они находятся.
