# ТурКонтур

ТурКонтур помогает специалисту по развитию туризма проверить изменения посещений, собрать программу и обосновать решение. Международная академия гостеприимства — заказчик пилота во Владимирской области.

- **Обзор** связывает событие с затронутыми программами. На **карте** можно выбрать группу и день, найти объект по названию, открыть паспорт и сравнить, как разные условия меняют программу.
- **Маршруты** превращают запрос специалиста в параметры, которые можно проверить и изменить. Можно собрать черновик на два или три дня в одном или нескольких городах России. Для гастротура сервис подбирает места с опубликованными сведениями о местной кухне или кулинарной программе. Доступность, часы и междугородний переезд без подтверждения прямо отмечены в результате и выгрузке.
- В рабочем пилоте предварительное расписание опирается на опубликованные часы объектов. Карта сохраняет направление, даты, размер и профиль группы. Паспорта показывают подтверждённые условия, ограничения и сроки новой заявки для услуг, для которых поставщик их публикует.
- **Погода** подгружается для города и даты каждого дня. В пределах семи дней от местной даты доступны температура, вероятность осадков и порывы ветра. Для уличной остановки можно проверить вариант в помещении, если он укладывается в расписание. Прогноз и пометки риска помогают выбрать программу. Часы, вместимость и запись проверяются отдельно. Источник для учебного MVP — [Open-Meteo](https://open-meteo.com/en/docs), данные по [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).
- **Вопрос ИИ** отвечает по статистике, картографическим источникам, паспортам объектов и журналу изменений. Ответ показывает ссылки и доступные даты.
- Интерфейс доступен на русском, английском и упрощённом китайском. Названия и выдержки из источников сохраняют оригинал там, где источник не публикует перевод.

## Запуск

Нужен Node.js 22 или новее. Дополнительные пакеты устанавливать не требуется.

- На macOS откройте «Launch.command». Сервер выдаст свободный локальный адрес и откроет его в браузере.
- Из терминала выполните `node server.mjs` в папке проекта и откройте [http://127.0.0.1:4173](http://127.0.0.1:4173).
- Для сравнения вариантов и классификации вопросов используется Ollama. `TUR_OLLAMA_MODEL` задаёт базовую модель, `TUR_OLLAMA_DETAIL_MODEL` — модель подробного разбора запроса. Параметры маршрута доступны для ручного ввода при занятости или недоступности модели.

## Демо для защиты

Для повтора с исходными данными задайте пустой каталог состояния перед запуском. Например, в терминале `TUR_STATE_DIR="$(mktemp -d)" node server.mjs`. Рабочий журнал останется в прежнем каталоге.

1. В «Источниках» откройте «Учебный пример» и запустите его. Сервис запишет изменение лимита с 25 до 12 человек и пересчитает две учебные группы.
2. Откройте [учебную программу на карте](http://127.0.0.1:4173/#impact?program=group-cn). Выберите второй день, откройте точку и паспорт Суздальского кремля. На обзоре можно открыть ту же программу из записи об изменении.
3. Переключите «Замена объекта» и «Два сеанса». Сравните точки и расписание, затем откройте «Сравнить условия» для тех же групп и дат. При новом лимите в исходном наборе выполнима одна программа из двух. Второй сеанс возвращает возможность провести обе. Согласуйте два сеанса по 9 человек с музеем.
4. Нажмите «Открыть программу». Сравните варианты расписания, при желании попросите ИИ учесть замысел программы, затем нажмите «Согласовать вариант». Версия появится в журнале решений и останется на контроле при следующих обновлениях. Для группы из Китая откройте «Программа на китайском» и выгрузите TXT с расписанием, правилами для подгрупп и проверками перед поездкой.
5. Откройте «Вопрос ИИ» и спросите, в какие месяцы за последние три года было меньше всего размещённых лиц во Владимирской области. Сверьте годы, значения и источник. Уточните часы работы объекта на выбранную дату и проверьте, где видно его опубликованный график.
6. В конструкторе по России введите «Казань на три дня, 12 человек, музеи, посещения до обеда, обязательно “Казанский кремль”». Проверьте извлечённые поля, соберите черновик, выберите день и скачайте программу. Для сравнения повторите с запросом «Москва и Казань на три дня, парки, без музеев».

### Проверка требований кейса

| Обязательный пункт | Что показать |
| --- | --- |
| Реальный внешний источник | «Источники» показывает статус подключений Wikidata и Росстата через Roschart |
| Статистика по запросу | Сервис выбирает ряд, ищет совместимый месячный выпуск и сравнивает заявленные периоды |
| Каталог из 15–30 объектов | 30 объектов в пилоте, из них 28 с опубликованными условиями или примечаниями |
| Мониторинг изменений | Две версии учебного аудита и журнал со старым и новым значением. Ошибки источников сохраняют последнюю копию |
| Оценка готовности | Паспорта со ссылками, датами, графиками, ограничениями и вопросами для подтверждения |
| Маршрут на два или три дня | Владимир и Суздаль, Муром на Оке, хрусталь и ремёсла, прогулка вдоль Нерли. Расчёт проверяет даты, посещения, переезды, питание и ночёвки |
| Управленческая рекомендация | Сравнить число выполнимых программ до и после улучшения. Сезонная гипотеза связывает ночёвки, опубликованные графики и пробелы в условиях |
| Сценарий для китайской группы | Отдельная версия программы на упрощённом китайском и выгрузка TXT |

В разделе «Маршруты» вкладка «Владимирская область · проверка» использует каталог пилота и опубликованные графики. Из учебной программы можно перейти к проверке по опубликованным условиям.

## Роль ИИ

Код обновляет источники, рассчитывает показатели, проверяет ограничения и строит варианты. Быстрый разбор сразу заполняет поля конструктора. По запросу локальная модель уточняет интересы, требования и названия, которые уже присутствуют в тексте. В чате она определяет тему сложного вопроса, а факты и ссылки извлекаются из подключённых данных. Для проверенных альтернатив модель помогает сравнить, какой вариант лучше сохраняет замысел поездки. Специалист решает, какую версию согласовать, и подтверждает поставщиков и бронирование.

## Происхождение данных

- Росстат через [API Roschart](https://roschart.ru/docs). Показатели «Численность размещённых лиц» и «Число ночёвок» по Владимирской области. Сервис ищет свежий совместимый месячный выпуск. Для воспроизводимости выпуск можно закрепить через `TUR_ROSSTAT_EDITION`. Месячные значения получены как разности накопительных итогов. При сбое используется последний доступный снимок.
- Wikidata через Wikibase API. Координаты и названия для части каталога. Для объектов опубликованы ссылки на сайты музеев и поставщиков или карточки Wikidata.
- Индекс населённых пунктов GeoNames доступен локально. Объекты для черновиков загружаются из OpenStreetMap, а при недоступности Overpass сервис ищет достопримечательности через MediaWiki. Для ряда городов, включая Тамбов, эти результаты дополняет подборка со ссылками на сайты объектов и региональные порталы. Найденные объекты и даты проверки сохраняются по городу и источнику в `national-catalog/` внутри каталога состояния. Снимки доступны после перезапуска, обновляются при запросе после истечения срока свежести и используются при сбое источника до 30 дней. Запросы пользователей, данные групп и маршруты в этот каталог не записываются. [GeoNames CC BY 4.0](https://www.geonames.org/export/), [OpenStreetMap ODbL](https://www.openstreetmap.org/copyright), [MediaWiki GeoSearch](https://www.mediawiki.org/wiki/API:Geosearch)
- Методика и контрольные объекты из двух таблиц МАГ. Условия визита в `data/demo-audit*.json` — учебные значения. Часы, лимиты, транспорт, бронь и язык обслуживания требуют подтверждения перед реальной поездкой.
- Опубликованные условия маршрута Владимир — Суздаль подключены по умолчанию из `data/published-*.json`. В паспортах и слое карты «Официальные графики» показаны часы на выбранный день, ссылки, условия записи, ограничения конкретных сеансов и вопросы для сверки. Снимок вручную сверили 17 ноября 2026 года. Основной [график ВСМЗ](https://vladmuseum.ru/ru/posetitelyam/times/index_rezim.php) покрывает период с 5 октября по 29 декабря 2026 года. Для других дат сервис обозначает пробел в графике. Оперативные места и факт брони у объектов проверяет специалист.
- Две учебные OTA-выгрузки показывают механику сопоставления предложений на ночь по дате заезда и числу гостей в номере. Карточки одинаковых отелей объединяются, а остатки разных источников отображаются отдельно. Фактическую доступность номеров для группы подтверждает отель.
- Внешние источники проверяются при запуске и раз в шесть часов работы сервера. Снимки, журнал изменений, согласованные версии и программы на контроле хранятся в `.runtime/state.json`. Переезды рассчитываются по схеме пилота. Фактический транспорт, брони и услуги подтверждаются отдельно.

## Подключение подтверждённых условий объектов

Если поставщики уже подтвердили условия для организованных групп, передайте абсолютный путь к согласованной JSON-выгрузке через `TUR_AUDIT_FEED_FILE`. Она загружается вместе с остальными источниками. Опубликованный график участвует в проверке конкретного времени. Квоты сборной экскурсии, вместимость отдельного зала и число номеров отображаются с указанной областью действия. Если файл временно недоступен или содержит ошибку, сервис сохраняет последний корректный снимок и показывает состояние источника. Условия вне периода действия требуют уточнения.

Верхний уровень содержит `version` (строка) и `objects` (объект с ключами из `data/catalog.json`). Каждая запись содержит `capacity` (человек), `minutes` (продолжительность посещения), `hours` (`[открытие, закрытие]` в часах местного времени), `off` (дни недели от `0` для воскресенья до `6` для субботы), `seasons` (`all`, `winter`, `spring`, `summer`, `autumn`), `language` (`interpreter`, `ru` или `null`), `access` (`true`, `false` или `null`), `booking` (`reservation` или `walk-in`), `sourceUrl` (HTTPS), `verifiedAt` (дата или время сверки ISO) и `validUntil` (включительная дата `ГГГГ-ММ-ДД`). В репозитории есть учебные условия. Выгрузка с подтверждением поставщиков подключается отдельно.

## Проверка

`node --test` проверяет правила расписания, российский индекс, подтверждение и пересчёт программ, разбор свободного текста, ответы со ссылками и недоступность внешних данных. Тесты запускаются без открытия браузера и без запуска сервера приложения.

## Источники карты

- Карта улиц и реки используют данные [OpenStreetMap](https://www.openstreetmap.org/copyright). Для переездов между городами используются сохранённые линии [OSRM](https://project-osrm.org/). Соединения между отдельными остановками внутри города показаны пунктиром по прямой.
- Координаты объектов пилота лежат в `data/map.json` со ссылками на источники. Для двух ресторанов показаны координаты комплекса, где они находятся.
- Лицензии Leaflet, Inter и PT Serif включены в проект.
